# 20 Viva Questions — Synthetic Medical Data Generator

Each answer is written to be **spoken in 30–60 seconds**, and each one is tied to
something actually measured in this project. The general strategy for a viva:
state the answer, give the number or the file that proves it, then volunteer the
caveat before the examiner has to find it.

---

## A. The core idea

### 1. What is synthetic data, and why would a hospital care?
Data generated by a model that imitates the statistical structure of real
records, without describing any actual person. A hospital cares because clinical
data is simultaneously the most useful and the most legally restricted data they
hold: a synthetic cohort can be sent to an external collaborator, put on a
teaching server, or used to prototype a risk model, without a data-use agreement
per project. The claim I am defending in this project is not "it looks real" — it
is "it is measurably useful *and* measurably leak-resistant", and those two
things trade against each other.

### 2. What is the difference between anonymised data and synthetic data?
Anonymisation **subtracts** information from existing rows that still refer to
real people — remove the name, coarsen the date, suppress rare combinations.
Synthesis **generates new rows** that refer to nobody. The practical difference:
anonymisation degrades utility monotonically and its failure mode is
re-identification by linkage; synthesis can preserve joint structure better but
its failure mode is that the model memorises and emits real patients verbatim.
That second failure mode is exactly why I measure an exact-copy rate and a
closest-record distance instead of trusting the method by name. **And the phrase
to remember: synthetic is not anonymous** — it is a different mechanism with a
different, measurable risk profile.

### 3. Your naive baseline resamples each column independently. What is it good for?
It is the control condition, and it is the reason my results mean anything.
Independent column resampling reproduces **every one-dimensional marginal
exactly, by construction** — so it wins on histograms and on KS and TV scores,
and it wins them trivially. It therefore proves that marginal fidelity is not
evidence. Its correlation gap is essentially the mean absolute correlation of the
real data, because it destroys every association. Any deep model that cannot beat
it on joint structure has learned nothing beyond the columns, which is the first
thing I checked and the reason criterion 1 exists.

## B. Method

### 4. Explain the VAE and the reparameterisation trick.
The encoder maps a record to a distribution in latent space — specifically the
vectors μ and log σ² — and the decoder maps a latent sample back to a record. We
want `z ~ N(μ, σ²)`, but sampling is not a differentiable operation, so gradients
cannot flow through it. The trick: take a fixed random draw ε ~ N(0, I) *outside*
the graph and compute `z = μ + σ ⊙ ε`. The randomness is now in a constant, and z
is a differentiable function of μ and σ. The loss is the ELBO: reconstruction plus
KL divergence between the encoded posterior and the standard normal prior.
In my implementation reconstruction is **split**: MSE on the numeric columns and
cross-entropy per categorical column, with the KL weight annealed from near zero
up to β_max.

### 5. Why one-hot for categoricals instead of just using the integer codes?
Because the codes have no ordering. `thal` takes values {3, 6, 7} meaning normal,
fixed defect, reversible defect. An integer encoding tells the model that 6 is
"more of" 3 and that 7 − 6 = 1 the same kind of quantity as 6 − 3 — none of which
is true, and it makes distances between categories meaningless. Mode-based
(one-hot) encoding expands a k-level column into k binary slots so the model
predicts a distribution over the levels, which also gives me a clean
cross-entropy target. The cost is dimensionality, which is why a dataset this
small still needs a narrow network.

### 6. Why anneal the KL term?
Early in training the decoder knows nothing, so the KL term — which pushes the
aggregate posterior toward N(0, I) — dominates the gradient and collapses the
latent code to the prior before the decoder has learned anything. That is
posterior collapse, and it produces output that is mush from the prior rather
than structure from the data. Annealing β from ~0 up to its target over the first
fraction of training lets reconstruction get a grip first. In my validation grid
β_max was one of the searched dimensions, and the winning value was **0.3**, not
the 1.0 default.

### 7. What is the loss-imbalance problem you found?
This is the most instructive bug in the project. Averaged MSE on min-max `[0,1]`
numerics is about **0.028** at a constant predictor; averaged cross-entropy on
categoricals is about **0.98** nats. That is a ~35× mismatch, so the optimiser
spends essentially all of its capacity on the categorical columns and the numeric
columns are never modelled. The symptom was that my first VAE had a Spearman
correlation gap *worse than the naive baseline* — which should be impossible for
a model that is supposed to learn associations. I did not change the metric; I
found the metric was right and the loss was broken. Adding a numeric loss weight,
tuned on validation, fixed it. Two things I would defend: the weight is one
dimension of a validation-only grid stored in `results/tuning_grid_heart.csv`, and
its optimal value **moved** when I changed the preprocessing — evidence the search
was doing real work rather than confirming a guess.

### 8. Why add noise to the decoder output at sample time?
Because MSE training *already assumes* a Gaussian observation with fixed
variance — minimising MSE is maximum likelihood under that model. So the correct
generative sample is `x = f(z) + σ ε`, and emitting `f(z)` alone is emitting the
conditional mean. The measured symptom of the mean-only sampler was systematic
under-dispersion: age spanning 33–71 against a real 29–76, cholesterol capped at
479 against a real 564, and a mean KS of 0.20 where the real-versus-real noise
floor is 0.13. Reading σ off the training reconstruction residuals and adding it
back dropped mean KS from 0.200 to 0.135 on validation, and the final 3-seed test
measurement is **0.129 against a noise floor of 0.128**. So this is not a hack bolted
on to flatter the metric — it is the sampler the loss function implies.

### 9. What is WGAN-GP and why did you pick it as your extra model?
A GAN whose critic estimates a Wasserstein distance rather than a Jensen-Shannon
one, with a **gradient penalty** that forces the critic to be 1-Lipschitz along
interpolations between real and fake, replacing the brittle weight clipping of the
original WGAN. I picked it deliberately over a conditional VAE so that the
adversarial model trains on the **exact same mode-based encoding** as my VAE. If
the two models share preprocessing, the difference in their results is
attributable to the training objective. With a conditional VAE I would have
changed two things at once and learned nothing clean. Honest caveat: on 181 rows
it is the least stable model in the study and it collapses onto a single diagnosis
class at some seeds; those runs report NaN with a note rather than a zero.

### 10. What did you have to fix in the `ctgan` package wrapper?
Three things. First, its default `batch_size` is 500, which against 181 training
rows means the sampler draws with heavy repetition every step — I clamp batch
size to the dataset. Second, when given a DataFrame it wants discrete columns
specified **by name**, not by integer index, and it raises a hard error on NaN in
continuous columns, so I assert cleanliness rather than let it fail obscurely.
Third, it returns numeric columns **unclipped** — it will emit an age of −4 — so
every CTGAN or TVAE sample passes through my sanitiser before being scored,
otherwise I would be comparing a model that respects medical ranges against ones
that do not.

## C. Privacy

### 11. Explain (ε, δ)-differential privacy in your own words.
Two datasets that differ by exactly one patient — one contains Alice, the other
does not. An ε-DP algorithm produces an output whose probability distribution
changes by at most a factor of e^ε when you swap that one person in or out. δ is
the probability with which the bound is allowed to fail entirely; I set it to
1/n_train, the standard convention, meaning the guarantee can fail with
probability at most one in n. Operationally: an adversary who sees the synthetic
table cannot reliably tell whether any particular patient was in the training
set. In DP-SGD this is bought by clipping every *individual* sample's gradient to
a fixed norm — so no single patient can move the parameters much — and then
adding Gaussian noise to the summed gradient. Crucially, ε is a property of the
**algorithm and its composition across steps**, not of the output table.

### 12. How did you actually achieve a target ε?
Through Opacus's accountant. I give it the target ε, δ = 1/n, the batch size, and
the number of epochs; it searches for the noise multiplier σ that makes the
composed privacy loss of all those noisy steps come out at or under the target.
For Cleveland it chose σ = **22.97** at ε = 1, **9.77** at ε = 3, **4.06** at ε = 10 and
**2.01** at ε = 30 — an 11× noise reduction across the sweep, over 3005 noisy steps.
Pima, with 2.5x the data, needed 9.84 down to 0.96. I report not
just the target but the σ chosen, the number of steps actually taken, and the ε
*actually spent* as measured by the accountant after training, which was slightly
under target at every setting. That matters: if I only reported the target, a
bug that skipped the noise would still print "ε = 1".

### 13. Why is the DP-VAE's utility so bad at ε = 1? Is that a bug?
It is the theorem, not a bug. Privacy cost under DP-SGD grows with the number of
noisy optimisation steps and shrinks with the noise magnitude; on 181 training
rows, satisfying ε = 1 forces σ ≈ 22.97 per clipped gradient update over 3005
steps. That is enough noise that the gradient signal is largely destroyed, so the
decoder learns almost nothing beyond the marginals. I measured the whole curve
rather than arguing it: TSTR AUC goes 0.514 → 0.526 → 0.594 → 0.580 across
ε = 1 → 30 against **0.948 for the non-private VAE trained at the same
optimisation budget**, and categorical total-variation goes 0.167 → 0.044 against
a 0.040 floor. So the trade-off is unambiguous in the metrics that matter.

One trap in that data worth naming, because it would be easy to get caught out
by: the **ELBO moves the wrong way**. Validation loss *falls* from 1.795 at ε = 1
to 1.654 at ε = 30, versus 1.929 for the non-private VAE. That is not the noisy
model learning better — a noise-collapsed encoder pushes the posterior onto the
prior, which drives the KL term toward zero and lowers the total. So the training
loss is **not** a valid model-quality metric here, and only the downstream
fidelity and utility numbers should be read as evidence. The correct conclusion
is not "DP does not work" but "DP at ε = 1 on a cohort of this size costs more
utility than the study can pay" — which is precisely the finding the experiment
was designed to produce.

### 14. Your membership-inference attack — describe it and its weakness.
The attacker holds the synthetic table and wants to know whether a specific
patient was in the training set. For each candidate patient they compute the
distance to the nearest synthetic record; if the generator memorised the training
data, *members* sit closer to the synthetic cloud than non-members do, so minus
that distance is a membership signal. I score it as an AUC over training members
versus held-out non-members. 0.5 is chance and is what I want. The weaknesses I
will name before you do: it is a **weak** attack — a single distance threshold,
no gradient access to the model, no shadow models, and no attribute-inference
variant. Both groups are drawn from the same real distribution, so even a
perfectly generalising model can land slightly off 0.5 from sampling noise, and
with a 61-patient test split the AUC itself is imprecise. So the MIA result is a
*relative* comparison across ε, not a certificate — the ε guarantee is the
stronger claim where it holds.

### 15. What is distance-to-closest-record and why is your ratio against real data?
For each synthetic row, the distance to the nearest real training row, in a
standardised encoded space. Taken alone it is misleading, because a genuinely new
*real* patient is also close to the training cloud — that is what "plausible
patient" means. So I compute the same quantity for held-out real patients against
the training set, and report the **ratio**. A ratio near 1.0 means synthetic rows
sit where new real patients would sit. A ratio well below 1.0 means the generator
crowded the training points, which is memorisation. I also report a "suspiciously
close rate": the fraction of synthetic rows closer to a training record than the
closest 5% of real unseen patients ever get. That converts a vague "small
distance" into a concrete threshold derived from the data.

### 16. Does an exact-copy rate of zero prove privacy?
No, and it is the weakest of my privacy claims taken alone. Zero exact copies
rules out only the most literal failure — emitting a training row verbatim. With
14 columns and continuous values, near-copies are still possible: a row that
differs in one column is not an exact copy but is highly identifying. That is why
the DCR ratio and the MIA AUC exist. Conversely, a *non-zero* exact-copy rate is
strong evidence of a problem, which is why I measure it at all. And the deeper
point: none of these bound an adversary with auxiliary data. Re-identification by
linkage to voter rolls or mobility data is a property of the attacker's dataset,
not of my table, and it is out of scope of anything I measured.

## D. Protocol and evaluation

### 17. How do you know you did not tune on the test split?
Three independent reasons, not one assertion. First, structurally: the tuner in
`synth/tune.py` receives `train` and `val` and **has no parameter through which
the test frame could arrive** — `tune()` literally never takes it. Second, the
selection score is a fidelity composite computed between the synthetic sample and
the **validation** rows, so no test information can enter the objective. Third,
the audit trail: every configuration considered, with its validation score, is
written to `results/tuning_grid_<dataset>.csv`, and the winning configuration is
serialised to `results/tuned_config.json` before the pipeline ever reads test.
I also volunteer the nuance: "test is touched once" means one *evaluation pass*
per model per seed, not one number overall, since mean ± std across three seeds
necessarily reads it three times. What is guaranteed, and what matters, is that
no fitting or selection decision consulted it.

### 18. What is the noise floor and why did you invent it?
It is not invented — it is the measurement I was missing. Comparing synthetic
data to only 61 held-out patients guarantees a non-zero KS statistic and a
non-zero correlation gap even if the generator were perfect, because two
*independent real samples* of that size disagree with each other. So I run the
identical metric code with real-train in place of synthetic, giving the floor:
**KS 0.128 and Spearman gap 0.099** on Cleveland. Every fidelity claim is then
made relative to that: naive is at 0.184 — nearly double the floor — and the tuned
VAE at 0.117, about 1.18× the floor. Without the floor, "the gap is 0.12" is an
uninterpretable number and I could have claimed victory at any value. The honest
consequence, which cuts against me: gaps **at or below** the floor are not
distinguishable from sampling noise, so I cannot claim the VAE is "essentially
perfect", only that it is statistically indistinguishable from more real data.

### 19. Why is your dataset only 303 rows, and does that invalidate the results?
It is the size of the public benchmark, which is a constraint I did not choose,
and I treat it as the central threat to validity rather than an embarrassment.
Concretely it bites in three places. The noise floor of 0.099 caps the resolution
of every fidelity number. Three seeds give a spread, not a confidence interval —
`std(ddof=1)` at n = 3 is itself very noisy. And differential privacy at small n
is punishing, which is exactly why the ε sweep collapses in utility. What I did
about it: I ran the identical protocol on Pima at n = 768 so the size effect is
visible rather than asserted, and I compare **both noise floors**, not just both
model scores, so the reader can separate "better model" from "less noisy
yardstick".

### 20. What would you do with more time, and what are the three biggest
     weaknesses of this project?
With more time: at least ten seeds with multiple-comparison correction across the
models and metrics; a stronger privacy baseline such as DP-CTGAN and a stronger
attack such as attribute-inference or a shadow-model MIA, because my attack is
deliberately weak; and a discretised-mixture numeric head of the TabVAE style, so
the point-mass and dispersion problems are handled inside the likelihood instead
of by a post-hoc transform and residual noise. I would also add subgroup fidelity
auditing, which I do not measure at all.

Biggest weaknesses, in order. One: **n = 181**, which caps what any metric here
can resolve. Two: because the numeric rank transform is fitted on the training
marginal, KS and TV are partly guaranteed by construction, so they are not the
metrics that distinguish these models — I state that rather than let the
histograms do the talking. Three: selecting the best model on validation and then
scoring it on test leaves a residual optimistic bias in the retention number that
I did not quantify, because three seeds is not enough data to estimate it.

## Quick-answer crib (one-liners for rapid-fire questions)

| Question | One-line answer |
|---|---|
| Split ratio and seed? | 60/20/20 stratified on diagnosis, seed 42, fixed. |
| Where is the generator's training data? | Train split only. Validation is used only for tuning and early stopping. |
| Loss function? | MSE per numeric column + cross-entropy per categorical column + annealed KL. |
| KL schedule? | Linear ramp to β_max over the first `anneal_epochs` epochs; β_max tuned on validation. |
| δ for DP? | 1/n_train, the standard convention. |
| Which accountant? | Opacus's PRV/RDP accountant, solving σ for a target ε over the actual step count. |
| Downstream classifiers? | Logistic Regression and Random Forest; accuracy, F1, AUC. |
| TSTR vs TRTR? | Train-on-synthetic-test-on-real versus the real-on-real ceiling; retention is their AUC ratio. |
| Exact copies found? | Measured per model; reported as a rate, and zero is treated as necessary-not-sufficient. |
| Diversity knob? | Categorical temperature 2^(d−0.5) and latent scale 1+0.5(d−0.5); d = 0.5 is neutral. |
| How are illegal values prevented? | Clip to plausible medical ranges, round integer columns, snap categoricals to the nearest legal level; validity rate is measured, not assumed. |
| Missing values? | Train-split median for numerics, mode for categoricals; Pima zeros treated as missing, `pregnancies == 0` kept. |
| Single-class synthetic data? | TSTR returns NaN with a `single_class_train` note, never a fake 0.0. |
| How many seeds? | 3, reported mean ± std, with `n_seeds_ok` recording when a mean is over fewer runs. |
| GPU used? | No. CPU-only; `torch.cuda.is_available()` was False on the run machine. |
| Reproduce in one command? | `python run_pipeline.py`, then `python make_figures.py`, then `streamlit run app.py`. |
